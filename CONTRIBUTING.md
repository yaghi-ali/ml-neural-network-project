# Contribution and publication rules

- One canonical location per project; link to existing repositories instead of copying them.
- State SI units, model assumptions, source/provenance and data origin.
- Use deterministic synthetic examples for a clean first run.
- Keep original attribution and upstream licences; do not relabel third-party code as original work.
- Do not commit passwords, tokens, customer material, laboratory recordings, personal data or local machine paths.
- Run the documented tests before proposing changes. Keep hardware actions opt-in.
- Report validation limits honestly; synthetic tests do not establish field performance.
